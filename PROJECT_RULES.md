# Правила проекта

## Офлайн-запуск

- Локально хранить иконки, шрифты и стили.
- Не зависеть от CDN и внешних ресурсов при запуске интерфейса.
- Все ресурсы, нужные для старта, должны попадать в инсталлер.

## Версионность

- При заметном изменении логики поднимать версию приложения.
- Синхронизировать версии в `package.json`, UI-заголовках и контекстных файлах.
- Для новых служебных файлов тоже вести версию в заголовке.

## Комментарии и читаемость

- Сложную логику сопровождать короткими поясняющими комментариями.
- Не комментировать очевидные строки без необходимости.
- Сохранять стиль и структуру существующего кода.

## Безопасность изменений

- Не ломать существующий функционал ради новой задачи.
- Менять только нужные участки кода.
- Проверять синтаксис после правок.

## Файлы и пути

- Работать с пользовательскими файлами вне папки программы.
- Не изменять исходные файлы, если задача требует создать производную копию.
- Сохранять результаты в предусмотренные рабочие папки.

## Рабочий порядок

- Сначала читать актуальные файлы, потом вносить изменения.
- Сохранять рабочую точку через понятные версии и контекстные файлы.
- Для релизов собирать инсталлер отдельно от кода.
