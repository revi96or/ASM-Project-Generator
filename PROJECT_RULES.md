# Правила проекта

## Офлайн-запуск

- Локально хранить иконки, шрифты и стили.
- Не зависеть от CDN и внешних ресурсов при запуске интерфейса.
- Все ресурсы, нужные для старта, должны попадать в инсталлер.

## Версионность

- При заметном изменении логики поднимать версию приложения.
- Синхронизировать версии в `package.json`, UI-заголовках и контекстных файлах.
- Для новых служебных файлов тоже вести версию в заголовке.

## Комментарии и читаемость

- Сложную логику сопровождать короткими поясняющими комментариями.
- Не комментировать очевидные строки без необходимости.
- Сохранять стиль и структуру существующего кода.

## Безопасность изменений

- Не ломать существующий функционал ради новой задачи.
- Менять только нужные участки кода.
- Проверять синтаксис после правок.

## Файлы и пути

- Работать с пользовательскими файлами вне папки программы.
- Не изменять исходные файлы, если задача требует создать производную копию.
- Сохранять результаты в предусмотренные рабочие папки.

## Рабочий порядок

- Сначала читать актуальные файлы, потом вносить изменения.
- Сохранять рабочую точку через понятные версии и контекстные файлы.
- Для релизов собирать инсталлер отдельно от кода.
- Если я прошу сделать задачу, сначала распиши мне план из 3-4 шагов 
   и спроси, согласен ли я.
- Перед тем как менять существующий код, убедись, что сделан git commit.
- Если я говорю "сохрани версию" или "зафиксируй точку", ты должен не просто поменять цифру 
   версии в коде, а сделать реальный git commit.
- Если после смены аккаунта или сессии изменился рабочий каталог, сообщи мне об этом.
- Если что-то сломалось, не пытайся переписывать код из памяти — сразу 
   предлагай сделать git reset, чтобы вернуться к рабочей точке.
- После выполненной задачи поднимай версию программы.

## Источник макросов

- Основной файл с макросами для переноса: `reference\PickAndPlaceAddin4.xlam`.
- Если я прошу посмотреть макрос, модуль, функцию или юзерформу, сначала смотри именно в этом файле.

## Список задач

- Пользоваться `TASKS.md` как списком задач.
- Отмечать выполненные и частично готовые задачи с пометкой версии программы, в которой задача была реализована.

## Журнал изменений

- После создания git commit добавлять информацию о нем в `CHANGELOG.md`.
